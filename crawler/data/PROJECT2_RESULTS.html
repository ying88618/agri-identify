  • 换 reranker 提升集中在 @5（+12.2pt），而 @20 持平（67.6%） → 典型「纯排序改善」，瓶颈在排序不在召回

5描述质量：prompt 迭代（示例与清单被模型照抄）

crawler/gen_vl_desc.py 保留了三版 prompt 与其教训注释。下表为番茄 140 样本的统计：

版本平均字数含「多角形」含「受叶脉限制」含「无明显病症」含「未见」
v372.784.3%81.4%2.9%23.6%
v464.50.0%81.4%2.1%27.1%
v556.10.0%0.0%1.4%67.9%
全量 620 条时 v3 的「多角形」占比为 59.4%（番茄 76%；番茄斑枯／玉米灰斑／马铃薯早疫／苹果锈病／草莓蛇眼 5 个类 100%）——数字见 gen_vl_desc.py 注释。

根因不是模型能力，而是提示词写法

  1. v3 的坑：判别特征清单写成「是否受叶脉限制（例如呈多角形）」，模型把括号里的示例当标准答案照抄。 一条特征出现在六成描述里就失去了区分度，反而把检索精准推向知识库中同样用该措辞的错误病害——这是番茄类召不回的根因之一。
  2. v4 的对策：删掉括号示例，并允许"形状不明显，不要硬套"。→「多角形」76.2% → 0.0%； 但「受叶脉限制」仍 73.8%（与 v3 持平）→ 说明根因不只是"示例被抄"，清单式提示本身就会让模型逐条"填上"。
  3. v5 的对策：整条删掉该清单项，并明确"各项只是提示方向，不要求逐条覆盖"。
效果（番茄 @5）：v3 25.0% → v4 28.6% → v5 37.9%（两版合计 +12.9pt）。

勘误（2026-09-15）：本文件早前版本把 v5 判为"模板塌缩、@5 提升不可信"，该结论错误。

错因是拿"含『未见』的比例"当作空洞度的代理指标 —— 而 v5 里的「未见霉层／粉状物／虫体」是合法的阴性判断 （有判别力：霜霉病才有霉层），与 v3 那种"照抄示例造成的假阳性"性质完全不同。

v5 的 prompt 恰恰禁止写"未见"占位词，模型仍写是出于语义必要，不是在灌水。v5 亦为全版本 @5 最高。

仍待处理：线上 core/vision.py 的 DESCRIBE_PROMPT 仍是含「示例输出」的旧版 （示例为"圆形黄褐色病斑、边缘有黄色晕圈、直径约 3~5mm"），与 v3 属同一类反模式，尚未切到 v5。

附：VL-Reranker 接口探测（重要负面结果）

平台的 /rerank 接口只接受字符串：

  • 传图文内容数组 → 400 Input should be a valid string
  • 穷举 9 种图片传参写法（query_image / images / image_url / query=dataurl …）→ image_tokens 全部 = 0，图片被静默忽略
  • 分数尺度佐证：同一组输入，VL-Reranker 给出 [0.0270, 0.0269, 0.0149]（几乎无区分度），而 bge 为 [0.7103, 0.3705, 0.1205]

→ 「用 VL-Reranker 做图文交叉打分」在该平台不可行，故改用多模态 LLM 做 listwise 重排（即 B2）。

9数据质量处置：Grape___Esca 剔除

Grape___Esca_(Black_Measles) 曾是 medium 置信度的近似映射（→ 葡萄轮斑病）。人工核对全部 20 张图后确认症状三项全不符：

判别点图（Esca 虎纹状叶症）葡萄轮斑病
形状不规则块状、受叶脉限制圆形，直径约 2cm
环纹无有深浅同心环纹
霉层无反面有浅褐色霉层

根因：PlantVillage 葡萄只有 3 类，而知识库有 49 种葡萄病害 —— Esca 在 KB 中无对应条目，只能勉强挑一个最像的。

处置：agri_eval_map.py 中改为 NO_MATCH；eval_agri_recall.py 的 load_samples() 增加过滤并打印剔除数。
影响：该坏标注系统性压低指标（尤其旧模型 @20 由 67.9% 拖到 66.6%），剔除后评测口径才干净。
